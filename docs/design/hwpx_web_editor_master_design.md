## 1. 단지 개요 (Project Overview)

| 항목 | 내용 |
|------|------|
| 대지 (Project root) | `office-analysis-engine` |
| 단지 목적 | HWPX 문서 인식·입력·반환 도구를 웹 브라우저로 공개 SaaS 배포 |
| 핵심 가치 | "사용자는 라벨이 인식된 폼에 값만 채우면, 한컴 호환 HWPX가 반환된다" |
| 타겟 입주자 (Users) | 공개 SaaS — 사내 직원, 거래처, 일반 사용자 |
| 편집 UX 결정 | (a) 폼 입력 방식 — 워드프로세서식 직접편집 (b)는 본 단지 범위 외 |

### 1-1. 단지 범위 외 (Out of Scope)

- 워드프로세서식 자유편집 (한컴 한글의 영역)
- HWP(바이너리) 직접편집 (HWPX 변환 후 처리)
- 인쇄·전자서명·결제 자동화 (CLAUDE.md §6 금지선)

## 4. 핵심 설계 결정 사항

### 4-1. 편집 UX = 폼 입력 방식 (확정)

```text
┌──────────────────────────┬──────────────────────────┐
│                          │  ▣ 입력 폼               │
│   [HWPX 미리보기]         │                          │
│                          │  공사명:  [____________]  │
│   ○○ 검측요청서           │  계약금액:[____________]  │
│   ─────────────          │  착공일:  [____________]  │
│   공사명: ____            │  준공일:  [____________]  │
│   계약금액: ____          │                          │
│   ...                    │  [ 저장 ]  [ 미리보기 ]   │
└──────────────────────────┴──────────────────────────┘
```

- 사용자는 라벨 인식된 입력 칸만 채움
- 본문 구조는 사용자가 깨뜨릴 수 없음 (안전)
- 모바일 호환 용이
- 우리 자산(라벨 사전 · writer · validation gate) 100% 활용

### 4-2. 외부 AI 연동 가능성 (대표님 질문에 대한 확정)

**XML 정밀진단동(B동)과 API 출입구(E동)가 완성되면, 편집기 UI 없이도 외부 AI가 직접 호출 가능합니다.**

```text
[외부 AI 앱]  ──HTTP POST──▶  [E동: API 출입구]
                                     │
                                     ↓
              ┌──────────────────────┴───────────┐
              │ {                                 │
              │   "documentId": "abc",            │
              │   "fills": [                      │
              │     {"label": "공사명",            │
              │      "value": "○○건축공사"},      │
              │     {"label": "계약금액",          │
              │      "value": "1,200,000,000"}    │
              │   ]                               │
              │ }                                 │
              └──────────────────────┬───────────┘
                                     ↓
                              [A동 인식 → B동 진단 →
                               C동 writer → D동 로그]
                                     │
                                     ↓
                          [완성된 HWPX 반환]
```

- 외부 AI는 라벨명과 값만 보냄
- 내부 동들이 알아서 정확한 셀에 작성
- 편집기 UI는 이 API의 **한 사용자**일 뿐

### 4-3. 폼 입력 방식의 자연스러운 확장

폼 입력에서 시작해도, 후속 공정에서 다음이 가능:
- 인식 안 된 라벨에 대한 사용자 추가 등록 (라벨 학습 루프)
- 특정 영역 자유 텍스트 입력 (제한적 직접편집)
- AI 자동 채움 (어시스턴트 기능)
- 다국어 라벨 사전 분기

반대 방향(직접편집 → 폼)은 어려움. 따라서 폼이 옳은 출발점.
