## 목표

`api_browser_e2e` 모듈의 매니페스트 승격 후보를 확정하고, 분류 계약 게이트 및 승격 후보 빌더의 기대값을 실제 현황에 맞게 갱신한다.

## 변경 이유

### 매니페스트 (`audit_hwpx_form_auto_fill_module_manifest.json`)

`api_browser_e2e` 모듈에 소스 파일 4개, 테스트 파일 6개를 추가 선언하여 실제 구현 파일과 매니페스트 간 불일치를 해소했다.

| 구분 | 추가 항목 |
|------|-----------|
| sourceFiles | `form_autofill_browser_smoke.mjs`, `form_autofill_browser_smoke.html`, `form_auto_fill_e2e_smoke.py`, `form_auto_fill_real_like_sandbox_batch.py` |
| testFiles | `test_hwpx_form_auto_fill_e2e_smoke.py`, `test_hwpx_form_auto_fill_real_like_browser_batch.py`, `test_hwpx_form_auto_fill_real_like_sandbox_batch.py`, `test_hwpx_form_autofill_browser_smoke.py`, `test_hwpx_form_autofill_frontend_contract.py`, `test_hwpx_form_writer_ui_connect.py` |

### 계약 게이트 / 승격 후보 빌더 테스트

`field_mapping`, `api_batch` 모듈이 이전 커밋에서 이미 승격 완료된 결과, 잔여 승격 후보가 34개 → 24개로 감소했다. 이에 맞춰 두 테스트 파일의 기대값(`stablePathMappedFiles`, `manifestPromotionCandidates`)을 `24`로 수정하고, 잔여 후보가 `user_flow_closeout` 모듈 단독임을 단언하는 조건을 추가했다.

## 검증 결과

- 분류 계약 게이트(`test_02_real_repo_contract_passes`) 수치 정합
- 승격 후보 빌더(`test_02_real_repo_candidates_pass`) 수치 정합
- `user_flow_closeout`만 잔존함을 `assert set(...) == {"user_flow_closeout"}`으로 명시 검증

> **건축 비유:** `field_mapping`·`api_batch` 세대 준공 후 잔여 미준공 세대 수를 세대대장에 재기재하고, `api_browser_e2e` 세대의 평면도(매니페스트)에 누락된 방(소스·테스트 파일)을 추가 등재한 공정이다.
